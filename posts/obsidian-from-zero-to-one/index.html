Obsidian 从零到一：我是怎么把写作和 iCloud 同步慢慢跑通的

发表于2026-05-02|更新于2026-05-02|效率工具
|浏览量:

最开始，我找笔记软件的标准其实很低。

能写，能存，别太卡，换台设备还能继续写，就够了。

那时候我主要在安卓和 Windows 上用，虽然谈不上多优雅，但至少还能用。真正把我逼着换思路的，不是写作本身，而是后来设备里多了 iPhone 和 iPad 以后，原来那套东西开始不兼容了。

不是这里不顺，就是那里接不上。不是同步别扭，就是换设备以后还得重新折腾。

也是从那时候开始，我才真正接触到 Obsidian。

这篇文章不打算写成“功能百科”，也不打算一上来就聊双链、图谱、插件市场。我想写的，是我自己这一路最真实的过程: 为什么会开始折腾，为什么最后选了 Obsidian，为什么又把同步方案定成了 iCloud，以及 Windows 端到底是怎么配通的。

我不是为了“第二大脑”去找 Obsidian 的。
我只是想把字安安稳稳写下去。

起因

一开始，我的使用场景其实很简单。

电脑上写一点，手机上记一点，想到什么就补什么。安卓和 Windows 阶段，这件事虽然也不算特别丝滑，但至少没把问题逼到台前。

可当 iPhone 和 iPad 加进来以后，问题就开始变得很具体了。

我慢慢发现，很多工具在“单设备写作”这件事上都没什么问题，但一到“多设备同步”就会露底。尤其当设备跨了不同系统以后，原本看起来没什么毛病的方案，突然就没那么顺了。

到这里我才意识到，我真正缺的已经不是一个“能打字的工具”，而是一套能把内容稳定带到不同设备上的方案。

接触 Obsidian

第一次接触 Obsidian 的时候，我其实也没觉得它有多神。

网上很多人都在讲它自由、强大、适合搭知识库，甚至会把它说得很玄。但这些东西对当时的我都不是重点，因为我那时候最关心的只有两件事:

  1. 它能不能让我老老实实写东西。
  2. 它能不能帮我把多端这件事理顺。

后来我才慢慢发现，Obsidian 真正重要的地方，不是“功能多”，而是“底层逻辑很清楚”。

先把 Obsidian 理解对

如果现在让我用一句话解释 Obsidian，我会这样说:

Obsidian 不是一套先有云、再有笔记的产品。
它更像是一个专门管理本地 Markdown 文件夹的写作工具。

这句话看起来平平无奇，但我后来回头看，很多坑其实都是因为一开始没把这件事理解透。

Obsidian 里经常会提到一个词，叫 Vault，中文一般翻译成“仓库”。

可这个词别想复杂了。所谓仓库，说白了就是一个文件夹。你的笔记、附件、图片、配置，基本都在这个文件夹里。

这件事一旦想明白，后面很多问题就清楚了。

  1. 你不是在“登录一个账号查看笔记”。
  2. 你是在“打开同一个文件夹”。
  3. 真正决定多端能不能一致的，不是界面，而是这个文件夹有没有被稳定同步。

所以到这里，问题就从“我该用什么笔记软件”，慢慢变成了“我该怎么同步这个仓库”。

同步方案，我看了不少，最后还是落回了 iCloud

那段时间我确实看了不少方案。

Obsidian Sync 是官方方案，逻辑完整，体验也更省心。
Git 很强，适合想保留版本记录的人。
像 OneDrive、Google Drive、Syncthing 这些，也都不是没人用。

但我后来越想越明白，我不能只看“理论上哪种最强”，而是要看“哪种最适合我现在这套设备”。

我当时的情况其实是这样的:

  1. 过去主要在安卓和 Windows 上写。
  2. 后来设备重心逐渐转到 iPhone 和 iPad。
  3. 真正让我不舒服的地方，主要也出在苹果端。

所以最后我的判断很直接: 既然问题主要出在苹果设备上，那同步方案就优先围着苹果端来想。

于是我最后敲定的是 iCloud。

我最后选 iCloud，不是因为它“最强”。
而是因为在我当时的设备结构里，它最顺手。

这里还得补一句实话。

截至 2026-05-02，Obsidian 官方文档对 iCloud Drive on Windows 的态度其实是偏保守的，明确提醒过它可能出现重复文件或文件损坏的问题。所以这并不是一套“官方最推荐的全平台方案”，而是我结合自己设备重心之后，权衡出来的一条路。

换句话说，这套方案更像是:

iPhone + iPad + Windows

而不是一套专门为了照顾安卓去设计的终极多端同步方案。

真正的转折点，不是装软件，而是把“仓库放哪”想明白

这一点我后来觉得特别关键。

我一开始也以为，先在 Windows 上建个文件夹，再想办法让手机和平板也去读它，不就行了吗？

后来发现不是这么回事。

如果你决定走 iCloud 这条路，更稳妥的思路应该反过来:

  1. 先在 iPhone 或 iPad 上创建仓库。
  2. 仓库位置直接放到 iCloud Drive/Obsidian/仓库名。
  3. 再让其他设备去打开这个已经存在的仓库。

这一步看着不起眼，实际上非常重要。

因为一旦仓库从一开始就放错地方，后面很多所谓“同步问题”，其实都是前面位置选错留下来的后遗症。

先把仓库放对地方。
再去谈怎么同步。

这个顺序不能反。

Windows 端到底是怎么接进来的

苹果端把仓库放进 iCloud Drive 以后，Windows 这边其实就不是“重新建一个仓库”，而是“把同一个仓库接进来”。

我后来真正跑通，大概就是下面这个过程。

第一步，先装 iCloud for Windows

这一步没什么花样，老老实实按 Apple 的方式来就行:

  1. 从 Microsoft Store 安装 iCloud for Windows
  2. 登录和 iPhone、iPad 一样的 Apple ID
  3. 打开 iCloud Drive

这一阶段我不建议自己手动模拟什么路径，也不建议先在别的盘里建一个“看起来像仓库”的文件夹顶上去。

先把 iCloud Drive 本身接通，比什么都重要。

第二步，去资源管理器里找到那个仓库

装好以后，Windows 资源管理器左侧一般会出现 iCloud Drive。

然后你要找的，不是什么自己想象出来的目录，而是:

iCloud Drive/Obsidian/你的仓库名

很多人刚开始会纠结路径到底在 C 盘还是 D 盘，或者为什么自己看到的层级和别人不太一样。

但说实话，比起盘符，更重要的是你打开的是不是 同一个 iCloud Drive 里的同一个仓库目录。

所以对新手来说，我更建议直接从资源管理器左侧的 iCloud Drive 入口进去找，不要一开始就执着于绝对路径。

第三步，把整个仓库设成“始终保留在此设备上”

这一步是我后来最想单独拿出来强调的一步。

如果仓库只是“云端有”，而不是“本地已经完整落下来”，那你写的时候其实很难完全放心。尤其 Obsidian 的仓库里通常有很多 Markdown 文件、配置文件、图片附件，本地常驻会让整件事安心很多。

我当时的做法就是:

  1. 打开资源管理器
  2. 进入 iCloud Drive
  3. 找到 Obsidian 的整个仓库文件夹
  4. 右键
  5. 选择 始终保留在此设备上

如果你用的是 Windows 11 的新版右键菜单，有时候还要先点一下 显示更多选项，才能看到 iCloud 相关命令。

Apple 官方文档里也提到了 Always keep on this device 这个功能，所以这一步不是“民间偏方”，而是确实值得开的设置。

如果你决定在 Windows 上配合 iCloud 用 Obsidian，
最好确保仓库不是“看得到”，而是“已经真的在本地”。

第四步，在 Windows 版 Obsidian 里打开这个仓库

前面都确认好以后，再打开 Windows 版 Obsidian，选择:

Open folder as vault

然后去打开刚才那个 iCloud Drive 里的仓库目录。

到这里，Windows 端才算真正接进来。

折腾到这里，我才慢慢把几件事想明白

这一段过程走完以后，我对 Obsidian 的理解其实比刚开始清楚多了。

1. 同步是同步，写作是写作

Obsidian 负责的是写作体验、结构组织、检索和管理。
至于同一个仓库怎么从一台设备到另一台设备，那是同步方案负责的事。

这两层分开想，很多问题就不会搅在一起。

2. 不要一上来就折腾插件

Obsidian 很容易让新手犯一个错误: 还没用顺，就开始装一堆插件、改主题、配模板、玩样式。

这些东西当然都可以折腾，但如果同步还没跑稳，你越早加东西，越容易把问题搞复杂。

我后来反而觉得，更合理的顺序应该是:

  1. 先把仓库位置放对
  2. 先把同步链路跑通
  3. 先稳定写一段时间
  4. 再慢慢加插件和工作流

3. 不要混用多套同步

同一个仓库，最好只走一套同步方案。

如果你一边走 iCloud，一边又想叠别的网盘、版本工具或者同步服务，最后真出了问题，排查起来会非常难受。

4. 备份这件事，永远不亏

因为 Obsidian 本质上就是一个文件夹，所以备份反而非常直接。你完全可以定期把仓库复制一份，或者打个压缩包。这样哪怕同步哪天出点小问题，至少原始文件还在自己手里。

到最后，我真正得到的其实不是“会用 Obsidian”

更准确一点说，我是终于把下面这件事想通了:

Obsidian 难的从来不是“怎么写”。
真正难的是“仓库放哪、怎么同步、哪一层负责什么”。

这一点想明白以后，后面的很多问题都会简单很多。

我后来再回头看这段过程，路径其实很清楚:

安卓和 Windows 阶段还能凑合写
到了 iPhone 和 iPad 开始觉得不顺
开始找替代方案
接触到 Obsidian
一开始没看懂
慢慢理解 Vault 和同步其实是两回事
最后把方案定在 iCloud
再把 Windows 的路径、本地保留、仓库接入这些细节一点点配好
最后真正把这套链路跑通

这才是我理解里的“从零到一”。

不是一上来把 Obsidian 玩得多高级，而是先把最基础、也最关键的那一步走通: 同一个仓库，在不同设备上都能安稳地打开、继续写、继续用。

最后

如果你现在也和我当时一样，只是想找一套能让写作安稳落地的方案，那我会建议你先别急着把 Obsidian 用复杂。

先把这三个问题想明白:

  1. 你的仓库放哪
  2. 你准备用什么同步
  3. 你能不能确认这个仓库真的落到了本地

这三件事一旦想明白，Obsidian 才会真正开始变得顺手。

软件本身不难。
难的是第一次把整套链路想清楚。
可一旦想清楚了，后面很多事就顺了。
